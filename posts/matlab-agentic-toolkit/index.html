我让 AI 帮我调用 MATLAB：matlab-agentic-toolkit 随笔

我个人并不太会用 MATLAB，也懒得从头系统学一遍。所以更现实的路线是：让 AI 帮我调用 MATLAB，把该跑的仿真、该画的图、该验证的东西先跑起来。

今天看到的仓库是 matlab/matlab-agentic-toolkit。我第一眼就觉得它挺适合我这种人：不是完全不会 MATLAB，但也谈不上熟；需要它的时候通常又很急，比如要跑个路径追踪仿真、画个轨迹图、看一下控制效果。

说白了，我不是想成为 MATLAB 高手。我是想在需要 MATLAB 的时候，让 Codex、Claude、Gemini 这三巨头能替我把 MATLAB 调起来，帮我跑代码、看输出、画图、改错。能少学一点是一点，先把结果跑出来再说。

它解决的是啥问题

以前让 AI 写 MATLAB，经常有一种很微妙的感觉：它写得像那么回事，但你不知道到底能不能跑。它可能会编一个函数名，或者凭印象写一段语法，最后还是得我打开 MATLAB 自己查、自己改、自己跑。那就有点失去偷懒的意义了。

这个 toolkit 的意义就是把 AI 从“嘴上会 MATLAB”往“真的能操作 MATLAB”推了一步。它不是单纯给 AI 塞一份文档，而是让 agent 能通过 MCP 去调用本地 MATLAB。

我的理解很简单：skill 负责寻思，MCP 负责动手。skill 告诉 AI MATLAB 这活儿大概该怎么干，MCP 让 AI 真的去 MATLAB 里跑一下。

skill + MCP 这套东西

它用的是 skill + MCP 的形式。这个组合我还挺喜欢，因为职责比较清楚。

  • skill：更像是经验包，告诉 AI MATLAB 的工作流、习惯、最佳实践，别上来就乱猜。
  • MCP：更像是手和脚，负责运行 MATLAB 代码、执行文件、跑测试、检测 toolbox。
  • agent：就是 Codex、Claude、Gemini 这些负责对话和拆任务的脑子。

装好以后，AI 可以做的事情就比较实在了：检测 MATLAB 版本、列出已安装工具箱、运行一段 MATLAB 代码、运行 .m 文件、跑测试、看 Code Analyzer 的检查结果。至少它不只是生成一段代码，然后把烂摊子留给我。

前置条件

这个东西不是云端魔法，前置条件还是得有。最重要的是：你本地得真的装了 MATLAB。没有 MATLAB，它也没东西可调。

  • 本地安装 MATLAB，官方要求是 R2021a 或更新版本。
  • 本机有 Git，因为安装和配置过程会拉仓库、找文件。
  • 有一个能用 MCP 和 skills 的 agent，比如 Claude Code、OpenAI Codex、Gemini CLI。

官方还提到 GitHub Copilot、Sourcegraph Amp 也在支持列表里。但对我来说，重点就是三巨头：Claude、Codex、Gemini。能把这几个都接上 MATLAB，就够我折腾一阵子了。

下载和安装

官方比较正经的安装方式，是下载 agenticToolkitInstaller.mltbx，然后在 MATLAB 里运行：

setupAgenticToolkit("install")

这个方式应该是最稳的。它会让你选择要装哪些 skill group，也能选择是给单个项目配置，还是全局配置。以后真要长期用，我应该会回到这条路线，老老实实装一遍。

但我这次比较偷懒。我直接把仓库链接丢给 Claude，让它帮我安。大概就是告诉它：

这是 MATLAB Agentic Toolkit：
https://github.com/matlab/matlab-agentic-toolkit

帮我按官方说明配置一下，让 Claude / Codex 可以调用本地 MATLAB。

官方也支持这种思路：克隆仓库，然后让 agent 执行“Set up the MATLAB Agentic Toolkit”。它会找最近的 MATLAB 安装，把 MCP server 放到 ~/.matlab/agentic-toolkits/bin/ 下面，再写 agent 的配置和 skills。也就是说，连安装这一步都可以让 AI 先替我试试。

当然，这种偷懒路线有个代价：它可能会把 skill group 装得比较全。后面如果发现上下文太多、触发混乱，再回来删也不迟。对我来说，先跑通，比一开始就追求完美配置更重要。

怎么确认装好了

装完以后，我觉得最简单的验证不是看配置文件，而是直接问 agent：

What version of MATLAB is running? List the installed toolboxes.

如果它能真的返回 MATLAB 版本和 toolbox，基本就说明 MCP 通了。接着可以让它跑一点简单代码，比如生成一个矩阵、画一张图、保存一张图片。别一上来就让它干大活，先确认管道是通的。通了以后再慢慢加难度。

我准备用在哪

我个人最想用的场景是在智能车里。比如做路径追踪的时候，需要看轨迹、误差、控制量变化，有些东西用 MATLAB 画图和仿真会比较顺手。但问题是，我又不想为了画个图、调个模型，把 MATLAB 从头学一遍。

所以我希望以后可以这样用：

我现在有一组智能车路径点和车辆轨迹数据。
请用 MATLAB 帮我画出参考路径、实际轨迹和横向误差曲线。
如果代码跑不通，先读取 MATLAB 报错，再修改。

或者做仿真时：

帮我用 MATLAB 搭一个简单的路径追踪仿真。
先用纯脚本生成参考路径和车辆轨迹，不要上来就搞复杂工程。
运行后把图保存出来，并解释结果哪里不对。

还有一些图形可视化也适合交给它。比如传感器数据、控制曲线、拟合结果、仿真对比图。MATLAB 的强项本来就在这些地方，只是我不想每次都和语法搏斗。让 AI 去搏斗，我负责看图。

给 AI 的几条规矩

虽然我想偷懒，但也不能完全放飞。尤其 MATLAB 经常会和数据文件、仿真文件、实验结果混在一起，agent 如果乱删乱改就很麻烦。所以我会提前说清楚：

  • 跑 MATLAB 前先说要跑什么，不要静悄悄执行一堆东西。
  • 不要删除原始数据、模型文件和实验结果。
  • 先写小脚本验证思路，不要一上来搞复杂工程结构。
  • 报错了先看 MATLAB 的真实输出，不要靠猜。
  • 能保存图就保存图，方便我直接看结果。

一点感想

我觉得这个仓库有意思的地方，不只是 MATLAB 本身，而是它代表了一种方向：AI 不只是聊天，也不只是生成代码，而是通过 MCP 去操作本地专业软件。专业软件不用被 AI 替代，但可以被 AI 调用。

对我来说，这就够了。我不会 MATLAB 没关系，我可以让 AI 帮我跑 MATLAB；我不想系统学也没关系，我可以先让它把智能车路径追踪和图形可视化这些事情跑起来。真遇到关键地方，再回头补知识。

一句话总结：我不是要精通 MATLAB，我是要让 MATLAB 变成 AI 能帮我调用的工具。
